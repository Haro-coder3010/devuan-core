PASO 3 — FASE 0.0 (Anfitrión) — Decisión sobre la partición EFI
Instrucción:
Has identificado que:

/dev/sda1 (100 MiB) es tu partición EFI actual, donde reside el cargador de arranque de tu sistema anfitrión (antiX).

/dev/sda3 (200 GiB) es la partición que destinarás al laboratorio (raíz cifrada).

La guía oficial de Devuan Core 2.2 asume un disco limpio donde se crean nuevas particiones. Sin embargo,
 en tu caso ya tienes un sistema operativo funcionando y deseas conservarlo.

Por favor, elige una de estas dos opciones:

Opción A (recomendada para conservar el host):

Usarás la partición EFI existente (/dev/sda1) sin formatearla.
Simplemente la montarás en /mnt/devuan/boot/efi y, al instalar GRUB, usarás --bootloader-id=Devuan 
para crear una entrada separada sin sobrescribir la de antiX.
Precaución: Tienes solo 100 MiB; puede ser suficiente para varios kernels, pero vigila el espacio. 
No formatearás, solo montarás.

Opción B (instalación limpia total):

Borrarás todas las particiones de /dev/sda y crearás una nueva tabla GPT con una partición EFI de
 512 MiB y una raíz de 200 GiB. Esto eliminará permanentemente antiX y todos tus datos en ese disco.

PASO 7 — FASE 0A (Anfitrión) — Apertura del contenedor LUKS
Instrucción:
Ahora que el contenedor LUKS ha sido inicializado, vamos a abrirlo para crear el mapeador 
lógico /dev/mapper/cryptroot, donde podremos formatear el sistema de archivos.

Ejecuta el siguiente comando en el anfitrión:

[bash]

sudo cryptsetup open /dev/sda3 cryptroot

Resultado esperado / Comportamiento interactivo:

El sistema te pedirá la frase de contraseña que acabas de configurar en el Paso 6.

Si la introduces correctamente, el comando finalizará en silencio (sin mensajes de salida).

Para verificar que se abrió correctamente, puedes ejecutar después (fuera de este paso) ls -l /dev/mapper/cryptroot; 
debería aparecer el nodo del dispositivo.

Posibles errores:

Si la contraseña es incorrecta, verás No key available with this passphrase. En ese caso, repite el comando.

Si aparece device-mapper: create ioctl on cryptroot failed: Device or resource busy, significa que el contenedor 
ya está abierto; puedes cerrarlo con sudo cryptsetup close cryptroot y volver a intentarlo.

[resultado]

PASO 21 — FASE 4 (Anfitrión) — Preparación del chroot (montaje de pseudo‑sistemas y configuración de DNS)
Instrucción:
Ahora que el sistema base está instalado, vamos a preparar el entorno chroot montando los sistemas
 virtuales (/dev, /proc, /sys, /run) que permitirán al sistema aislado comunicarse con el hardware y la red. 
 También inyectaremos un archivo resolv.conf dentro del chroot para que tenga acceso a internet durante la configuración.

Ejecuta el siguiente bloque de comandos en el anfitrión:

bash

sudo mount --bind /dev /mnt/devuan/dev && \
sudo mount --bind /dev/pts /mnt/devuan/dev/pts && \
sudo mount -t proc proc /mnt/devuan/proc && \
sudo mount -t sysfs sysfs /mnt/devuan/sys && \
sudo mount -t tmpfs tmpfs /mnt/devuan/run && \
sudo rm -f /mnt/devuan/etc/resolv.conf && \
sudo tee /mnt/devuan/etc/resolv.conf << EOF
nameserver 1.1.1.1
nameserver 8.8.8.8
EOF

Resultado esperado:

Los cinco montajes se ejecutarán en silencio (sin mensajes).

rm -f eliminará cualquier resolv.conf previo (si existía).

tee mostrará en pantalla las dos líneas nameserver ... confirmando que se escribió correctamente.

No debe aparecer ningún error.

[resultado]

nameserver 1.1.1.1
nameserver 8.8.8.8

PASO 27 — FASE 6 (Dentro del chroot) — Instalación de utilidades base, herramientas de diagnóstico y soporte criptográfico
Instrucción:

 para la administración, diagnóstico y el soporte crítico para el cifrado LUKS. Este paso es fundamental porque incluye
  cryptsetup-initramfs, que permite que el initramfs pueda descifrar la raíz en el arranque.

Ejecuta el siguiente comando dentro del chroot:

dosfstools -y

Resultado esperado:

APT descargará e instalará todos los paquetes listados.

Al final, no debe haber errores de dependencias ni de firmas.

Es normal que aparezcan advertencias de perl sobre locales (se configurarán más adelante).

La instalación de cryptsetup-initramfs es crucial; asegura que los hooks de LUKS se integren en la imagen de arranque.

Luego te preguntará por el tamaño de la fuente; puedes elegir el valor predeterminado (16 o el que aparezca por defecto).

Si aparece una pregunta como "Keep current configuration?" o "Use default settings?", responde afirmativamente (Sí / Yes).

Se aceptaron los valores predeterminados para la fuente y tamaño.

PASO 28 — FASE 6.5 (Dentro del chroot) — Configuración de /etc/crypttab para el mapeo persistente
Instrucción:
Necesitamos decirle al sistema qué dispositivo físico debe abrir en el arranque para obtener la raíz cifrada. 
Para ello, escribiremos el archivo /etc/crypttab con el UUID de tu partición /dev/sda3. Sigue estos pasos en orden:

Abre una segunda terminal en el sistema anfitrión (sin salir del chroot) y ejecuta:

bash

sudo blkid /dev/sda3

Copia el valor que aparece después de UUID="..." (por ejemplo, 0b83f074-e2fc-4a2f-a78d-82e67df2320e).

Dentro del chroot (en la terminal donde tienes el prompt root@devuan:/#), ejecuta el siguiente comando reemplazando <TU_UUID> por el valor que copiaste:

bash

echo "cryptroot UUID=<TU_UUID> none luks,discard,initramfs" > /etc/crypttab

Ahora que tienes el UUID de /dev/sda3 (0b83f074-e2fc-4a2f-a78d-82e67df2320e),
 escribe el archivo /etc/crypttab dentro del chroot y verifica su contenido.

Ejecuta el siguiente comando dentro del chroot (copia y pega el bloque completo):

bash

echo "cryptroot UUID=0b83f074-e2fc-4a2f-a78d-82e67df2320e none luks,discard,initramfs" > /etc/crypttab && cat /etc/crypttab


Resultado esperado:

El comando echo se ejecutará en silencio. Para verificar que se escribió correctamente, puedes ejecutar 
(por tu cuenta, fuera del paso) cat /etc/crypttab; deberías ver una línea como:

text

cryptroot UUID=0b83f074-e2fc-4a2f-a78d-82e67df2320e none luks,discard,initramfs

Nota importante:

El nombre cryptroot debe coincidir con el mapeador que usaste al abrir el contenedor (Paso 7).

La opción initramfs es crucial para que los hooks de cryptsetup se activen durante el arranque.

Ejecuta ambos comandos (el blkid en el host y el echo en el chroot), confírmame que el archivo quedó escrito correctamente y continuaremos con el Paso 29 (instalación del kernel).

[resultado]

cryptroot UUID=0b83f074-e2fc-4a2f-a78d-82e67df2320e none luks,discard,initramfs

PASO 45 — FASE O1 (Dentro del chroot) — Configuración de tmpfs para /tmp y /var/tmp
Instrucción:
Agregaremos dos líneas al final del archivo /etc/fstab para montar /tmp y /var/tmp como sistemas de archivos en RAM (tmpfs). 
Esto mejora el rendimiento y reduce las escrituras en el disco, pero el contenido de /var/tmp no persistirá entre reinicios. 
Esta optimización es recomendada para un sistema Core.

Ejecuta el siguiente comando dentro del chroot:

bash

cat << 'EOF' >> /etc/fstab

# Volatilización de temporales (v2.2)
tmpfs /tmp     tmpfs defaults,noatime,nosuid,nodev 0 0
tmpfs /var/tmp tmpfs defaults,noatime,nosuid,nodev 0 0
EOF

Resultado esperado:
El comando se ejecutará en silencio (sin salida visible). Puedes verificar que las líneas se añadieron 
correctamente con tail -n 5 /etc/fstab, que debería mostrar las dos últimas líneas con tmpfs.

Advertencia:
Recuerda que el contenido de /var/tmp se perderá al reiniciar. Si necesitas persistencia en /var/tmp,
 elimina esa línea del fstab después de la instalación.

El sistema sigue fallando al introducir la contraseña LUKS con el mismo error: Invalid passphrase y disk not found. A pesar de que la contraseña funciona desde antiX y todos los UUIDs son correctos, GRUB no logra descifrar el disco.

Incidencia 4: Entrada UEFI volátil
Síntoma:
La entrada Devuan creada con efibootmgr desaparecía después de algunos reinicios o al arrancar antiX.

Diagnóstico:
El firmware UEFI a veces restablece el orden de arranque o elimina entradas que no pueden validarse correctamente.

Solución probada:
Reinstalar GRUB en modo removible (--removable), lo que obliga a UEFI a detectar el cargador en la ruta estándar /EFI/BOOT/BOOTX64.EFI. Esto garantiza que siempre sea detectable aunque la entrada NVRAM se pierda.

bash
grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=Devuan --removable --recheck
Resultado: La entrada UEFI se creó y persistió, pero el fallo de autenticación LUKS continuó.

🧠 CONCLUSIONES Y ANÁLISIS
El problema es exclusivamente de GRUB y su manejo de LUKS.

La contraseña funciona desde antiX, los UUIDs son correctos, y la configuración de GRUB parece estar bien formada.

El error Invalid passphrase suele ocurrir cuando GRUB no puede acceder al dispositivo o cuando el comando cryptomount no se ejecuta correctamente.

Posibles causas del fallo de cryptomount:

Falta de módulo luks en el núcleo de GRUB. Aunque se especificaron en --modules, es posible que el binario de GRUB en la EFI no los incluya.

El formato del UUID en cryptomount es incorrecto. GRUB espera el UUID sin guiones y con prefijo cryptouuid/. Aunque el script lo escribe sin guiones, GRUB internamente lo convierte, pero podría haber problemas de formato.

El firmware UEFI bloquea el acceso al disco cifrado. Algunos sistemas UEFI tienen restricciones de seguridad que impiden a GRUB leer dispositivos cifrados antes de cargar el sistema operativo.

La entrada UEFI y el GRUB instalado son correctos, pero el descifrado falla en tiempo de arranque.
